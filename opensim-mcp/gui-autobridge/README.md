# Automatic OpenSim GUI bridge

This original NetBeans module registers a startup hook and runs the existing
authenticated Jython bridge on Swing's event thread. It does not add a second
RPC protocol or change OpenSim Core.

## Install / remove

The release ZIP includes dist/org-opensim-mcp-autobridge.jar, so Java compilation
is not needed by users. Run connect_gui or start the MCP server first.

~~~powershell
$osim = 'E:\OpenSim 4.6'
$scratch = 'E:\simulink\_codex_tmp\opensim-mcp-runtime'
.\gui-autobridge\install-autobridge.ps1 -OpenSimRoot $osim -BootstrapScript (Join-Path $scratch 'gui-bridge\start_gui_bridge.py')
# Restart the GUI:
.\scripts\start-gui.ps1 -OpenSimRoot $osim -TempRoot $scratch
# Remove only this plugin (close the GUI first):
.\gui-autobridge\install-autobridge.ps1 -OpenSimRoot $osim -Uninstall
~~~

The installer writes three files inside the OpenSim cluster: modules/
org-opensim-mcp-autobridge.jar, the adjacent .properties file, and config/Modules/
org-opensim-mcp-autobridge.xml. It supports -WhatIf and never changes core DLLs.
Write access to that installation is required. Install separately for each GUI.

Bootstrap path precedence: Java property opensim.mcp.gui.bootstrap, environment
OPENSIM_MCP_GUI_BOOTSTRAP, then the adjacent UTF-8 .properties file.
There is no hard-coded machine path in the plugin. The configured script is
trusted executable code; install only a bootstrap generated by your own MCP.

The hook waits for the file to exist, runs once per GUI process, and stops
retrying after dispatch. The Jython bootstrap records failures in startup_error.txt;
Java initialization failures appear in the GUI's messages.log.
If changing TempRoot, reinstall with the new bootstrap path and restart the GUI.
If a same-version JAR has been replaced, use a fresh dedicated GUI cache to avoid
NetBeans reusing cached classes. A stopped bridge stays stopped until restart or
manual bootstrap.

One GUI may use a given bridge folder. Parallel GUI instances require independent
configurations/temp roots. Auto attachment does not continuously merge API/GUI
model edits. Always verify connect_gui.connected and get_current_model.

## Build from source

Requires a Java JDK with javac/jar and the target GUI's installed Java modules.
The tested binary targets Java 8 bytecode and was built against GUI 4.6_beta.
Its imports are also available in installed OpenSim 4.3; startup on 4.3 is not part
of the GUI regression record. Rebuild/retest against other GUI distributions.

The Java startup module remains version 0.3; v0.4 functionality is in the Python
bridge it reloads on each launch. No new JDK installation is required for that update.

~~~powershell
.\gui-autobridge\build-autobridge.ps1 -OpenSimRoot 'E:\OpenSim 4.6' -JdkHome 'E:\Tools\jdk8' -TempRoot 'E:\simulink\_codex_tmp\opensim-build'
~~~

Compilation uses a unique temporary subfolder and removes it after the build.
The resulting JAR is the deliverable in dist/. A JDK is not bundled.
